# Obsidian 知识库管理指南

知识库就是项目根目录下的 `kb/` 文件夹——**用 Obsidian 直接“打开文件夹作为仓库”即可**，客服/业务同事日常维护 Markdown，无需接触数据库或代码。

## 1. 快速上手

```
1. 安装 Obsidian → 「打开本地仓库」→ 选择项目的 kb/ 目录
2. 新建/编辑 .md 文件（遵守下方的 front matter 规范）
3. 运行 python scripts/sync_kb.py 同步入库（幂等，可反复执行）
4. 前端「知识库问答」立即可检索到新内容
```

也可以在服务运行时调用接口同步：`POST /api/kb/sync`。

## 2. 文件规范（front matter 必填四项）

```markdown
---
title: 滞箱费与免箱期规则
category: 账单
tags: [滞箱费, 免箱期, 集装箱, 费用]
updated_at: 2026-08-20
---

# 滞箱费与免箱期规则

## 什么是滞箱费与免箱期
……（正文用小节标题 + 短段落/列表，检索效果最好）
```

| 字段 | 说明 |
|---|---|
| `title` | **同步键（唯一）**，文件改名不影响已入库文档的对应关系；缺省用文件名 |
| `category` | 业务分类（账单/运输/关务/仓储…），供前端筛选展示 |
| `tags` | Obsidian 标签，行内数组写法 |
| `updated_at` | 文档更新日期，缺省取文件修改时间 |

## 3. 同步与幂等机制（scripts/sync_kb.py）

- **同步键**：`title`。内容变更 → 更新正文并**重建该文档全部切块**；内容未变 → 无副作用；
- **删除**：kb/ 里删掉的文件，其文档与切块也会从库中移除；
- **切块策略**：按小节标题/段落切成约 350 字符的块（上限 600），每块自带小节标题（标题词参与检索命中）；
- 重复执行结果一致，Obsidian 保存后随手同步一次即可。

```
$ python scripts/sync_kb.py
[完成] 知识库同步：扫描 10 个文件 | 新增 0 | 更新 1 | 移除 0 | 切块 44 块
```

## 4. 检索与回答机制（RAG）

```
用户问题 → 分词（中文 bigram + 英文单词）→ BM25 检索 Top-3 切块
        → 命中置信达标：拼 Prompt 交给 LLM 生成（或 mock 模式直接摘录）
        → 回答末尾自动追加【来源：文档标题】，前端可点开源文
        → 检索无命中 / 置信不足：回复“知识库中暂无相关内容，建议转人工客服”
```

置信判据（`app/rag.py`）：BM25 最高分达标，且命中的信息词 ≥2 个（疑问词与通用词已被停用）；仅命中 1 个强特征词时要求该词出现在文档标题中。每次问答都会写入 `qa_logs` 留痕，支撑可用率评测。

## 5. 维护建议

- **一篇 FAQ 回答一类高频问题**，多用小节标题（## 费用标准 / ## 常见问题）——它们是检索的关键锚点；
- 语气面向客户，直接可引用（mock 摘录模式下会整段展示）；
- 每季度审阅 `updated_at` 超过 90 天的文档；
- 新增文档后用 demo 问题自测：如新增“退仓流程”，就问“退仓怎么操作”看是否命中并带来源。
