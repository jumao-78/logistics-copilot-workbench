## 2. 背景与目标

### 2.1 背景

货代/跨境物流公司的客服团队每天通过邮箱、微信、电话接收客户求助，主要问题集中在三类：

1. **重复查询多**：约 45% 的消息是流程/费用类重复咨询（滞箱费怎么算、清关要什么资料），每条人工回复约 5 分钟；
2. **抄写录入慢且易错**：消息里的提单号、柜号、港口要人工读出并抄进系统，每单约 3 分钟，抄错单号会引发二次返工；
3. **流程知识在老员工脑子里**：新人遇到流程问题只能逐个请教，上手周期长。

以上现状使客服大量时间消耗在低价值重复劳动上，且服务质量依赖个人经验。

### 2.2 目标

为客服团队提供一个轻量级 AI 工作台，实现：

- 非结构化客户消息 → **自动结构化**为工单（分类、紧急度、关键字段、建议回复）；
- 高频流程问题 → **知识库问答直接给出带来源的答案**，答不上自动建议转人工；
- 运营状态 → **数据看板**可视化（工单量、AI 处理占比、超时风险）；
- 无大模型环境时系统可用性不受影响（自动降级规则模式）。

### 2.3 成功指标

| 指标 | 目标值 | 当前实测（模拟数据） |
|---|---|---|
| 工单分类准确率 | ≥ 90% | 规则模式 100%（20/20）；LLM 模式 95% |
| 关键字段提取准确率（提单号/柜号/港口） | ≥ 90% | 100%（10/10，无幻觉） |
| 知识库问答拒答正确率（无关问题不编造） | = 100% | 域外问题全部转人工 |
| AI 自动处理率（模拟口径） | ≥ 40% | 48%（320 条模拟工单） |
| 演示可用性 | 断网/无 Key 全流程可演示 | 达成（自动降级规则模式） |

## 3. 用户场景

### 3.1 目标用户

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 客服专员（新人/熟手） | 每天处理 60~80 条客户消息 | 少抄写、快速回、不会就查 |
| 客服主管 | 管理团队响应时效与质量 | 看清积压/超时/风险，能调度 |
| 业务支持（关务/结算） | 处理专业问题 | 工单信息完整准确 |

### 3.2 用户故事

- 作为**客服专员**，我希望把客户消息一粘贴就自动生成工单字段和回复草稿，以便我核对后直接发送；
- 作为**客服新人**，我希望有问题能问知识库并看到答案出处，以便不用打扰老员工；
- 作为**客服主管**，我希望一屏看到今日工单量、AI 处理占比和超时工单，以便安排人手；
- 作为**客服专员**，我希望 AI 不确定时明确说"转人工"，以便我不会把错答案发出去。

### 3.3 使用场景

**场景 1：消息自动结构化**
- 触发条件：客服收到客户消息（邮件/微信/电话记录）
- 用户行为：粘贴到工单台（或批量导入 CSV），点击 AI 处理
- 预期结果：生成结构化工单（分类/紧急度/意图/提单号/柜号/港口），附建议回复；同一消息 30 分钟内重复提交会被查重拦截

**场景 2：知识库问答**
- 触发条件：客户问流程/费用类问题，客服不确定答案
- 用户行为：在知识库页输入问题
- 预期结果：命中 → 回答 + 【来源】文档可点开核对；未命中 → 回复"知识库中暂无相关内容，建议转人工客服"

**场景 3：主管看板**
- 触发条件：每日晨会/复盘
- 用户行为：打开总览页
- 预期结果：今日工单量、AI 自动处理率、平均首响、高紧急占比、超时工单队列、按小时趋势

**场景 4：演示/降级**
- 触发条件：无 API Key、断网或 LLM 调用失败
- 预期结果：单条粒度自动降级规则模式（正则提提单号/柜号 + 关键词分类 + 模板回复），全流程不中断

### 4.2 功能详情（核心功能）

#### 4.2.1 消息结构化（P0）

**需求描述**：输入任意客户消息文本，输出 8 个结构化字段 + 建议回复。

**交互流程**：
1. 客服在工单台输入框粘贴消息（≤3000 字符）；
2. 系统调用大模型（temperature=0，严格 JSON 输出）或规则模式；
3. 返回分类/紧急度/意图/提单号/柜号/起运港/目的港 + 建议回复；
4. 入库并展示结果卡，建议回复支持一键复制。

**字段规则**：

| 字段 | 取值 | 校验规则 |
|---|---|---|
| category | 仓储/运输/关务/账单/其他 | 不合法回退"其他" |
| urgency | 高/中/低 | 不合法回退"中" |
| intent | 查询/催件/投诉/改单/索赔/预约/其他 | 不合法回退"其他" |
| bill_no | 4 字母 + 9~10 位数字 | 无则 null，不编造 |
| container_no | 4 字母 + 7 位数字 | 无则 null |
| pol / pod | 港口中文名（清洗口语尾缀） | 无则 null |

**异常处理**：
- LLM 调用失败/超时/输出非 JSON → 该条自动降级规则模式，管道不中断；
- 消息超长（>3000 字符）→ 422 提示；
- 重复消息（30 分钟内同内容）→ 409 提示"疑似重复工单 #id"。

#### 4.2.2 知识库问答（P0）

**需求描述**：基于 `kb/` 目录 FAQ 文档回答物流流程问题，回答必须可溯源。

**交互流程**：
1. 客服提问；系统对问题分词（中文 bigram + 英文词）；
2. BM25 检索知识库切块，取 Top-K；
3. 置信判据过滤（信息词覆盖 + 相关性阈值）：不达标 → 直接回复转人工话术；
4. 达标 → LLM 依据片段生成回答（或 mock 摘录），末尾**强制标注【来源：文档名】**；
5. 问答全量写入 qa_logs（供评测与审计）。

**异常处理**：
- 知识库无匹配 → 固定话术"知识库中暂无相关内容，建议转人工客服"（宁可转人工，不编造）；
- LLM 失败 → 降级摘录模式（直接引用检索片段）。

#### 4.2.3 运营看板（P0）

**需求描述**：所有指标由 SQL 聚合，前端零写死数字。

**指标定义**：

| 指标 | 口径 |
|---|---|
| 今日工单量 | created_at 为当天的工单数 |
| AI 自动处理率 | 状态=AI已处理 ÷ 总数 |
| 平均首次响应 | replied_at − created_at 均值（方言分支计算） |
| 高紧急占比 | urgency=高 ÷ 总数 |
| 超时工单 | 待处理超 4 小时 或 响应超 4 小时 |
| 按小时趋势 | 今日 09:00 起逐小时创建量（新增/AI/人工三线） |

## 5. 非功能需求

### 5.1 性能需求
- 单消息结构化：LLM 模式 2~6 秒（glm-4-flash），规则模式 <100ms；
- 看板聚合查询：320 条数据 <200ms（SQLite 单机）；
- 前端请求统一 25 秒超时（AbortController）。

### 5.2 安全需求
- 数据库连接只从 `DATABASE_URL` 读取，ORM 无 SQLite 专属语法（可切 PG/MySQL）；
- 提示词注入防护：消息中指令性内容一律视为数据；
- 可选 API Token 鉴权（Bearer / X-API-Key）+ CORS 可配置；
- `.env`（API Key）不入版本库。

### 5.3 兼容性需求
- 无 Key/断网 → 规则模式全流程可用；
- 前端离线自足（字体/图表库本地化，无 CDN 依赖）；
- 桌面浏览器 1440px 优先（企业内网场景）。

## 6. 界面原型

### 6.1 页面流程

```
总览（今日运营）→ 工单台（处理工单 / 人工确认）→ 知识库（查询流程问题）
智能管道（查看 AI 处理链路）→ 数据分析（长期价值）→ 设置（工作区状态）
```

### 6.2 关键页面

| 页面 | 说明 |
|---|---|
| 总览 | Hero + 今日 KPI + 按小时趋势 + 高优队列 + AI 运营动态 |
| 工单台 | 三栏：工单流（含新建/筛选）/ 货物信息与处理链路 / AI 决策中心（风险/意图/建议动作/生成回复/知识依据） |
| 知识库 | 搜索 + 回答卡 + 证据面板 + 检索管道 + 相关问题 |
| 智能管道 | 5 节点编排视图（跟踪/知识/推理/回复等）+ 自定义消息运行 + 人工确认 |
| 数据分析 | AI 效率指标 + 处理漏斗 + Agent 绩效 + 风险智能 + 改进中心 |
| 设置 | 系统概览 / AI 模型 / 连接与通道 / 安全与治理 / 高级配置 |

## 8. 风险评估

| 风险类型 | 风险描述 | 影响 | 应对措施 |
|---|---|---|---|
| 技术 | LLM 输出不稳定（同一输入偶发不同结果） | 中 | temperature=0 + JSON 校验 + 失败降级规则模式；评测集持续回归 |
| 技术 | 关键词检索无语义泛化，同义改写可能不命中 | 中 | 宁可转人工不编造；语料扩大后升级向量检索（已预留） |
| 业务 | 模拟数据不能代表真实业务分布 | 高 | 上线前用真实历史工单离线评测一个月（已列入下一步计划） |
| 资源 | 无真实外部系统（船司 API/邮件）对接 | 中 | 接口边界预留；演示以模拟渠道代替并明确标注 |
