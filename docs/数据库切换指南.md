# 数据库切换指南：SQLite → PostgreSQL / MySQL

本项目的数据库连接**只从环境变量 `DATABASE_URL` 读取**，默认 `sqlite:///data/copilot.db`。ORM 层（SQLAlchemy）未使用任何 SQLite 专属语法，切换数据库只改环境变量，不改一行代码。

## 1. 三种数据库的连接串

```bash
# SQLite（默认，零配置）
DATABASE_URL=sqlite:///data/copilot.db

# MySQL 8.x（需 pip install pymysql）
DATABASE_URL=mysql+pymysql://user:password@localhost:3306/logistics_copilot?charset=utf8mb4

# PostgreSQL 14+（需 pip install "psycopg[binary]"）
DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/logistics_copilot
```

配置方式二选一：

```bash
# 方式一：写入项目根目录 .env（推荐，参考 .env.example）
echo "DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/logistics_copilot" >> .env

# 方式二：启动前设置环境变量
# PowerShell:  $env:DATABASE_URL="postgresql+psycopg://..."
# Git Bash:    export DATABASE_URL="postgresql+psycopg://..."
```

## 2. 切换步骤（以 PostgreSQL 为例）

```bash
# ① 安装驱动
pip install "psycopg[binary]"        # MySQL 则: pip install pymysql

# ② 建库（可选手工建表：psql -f docs/schema.sql）
createdb logistics_copilot

# ③ 设置 DATABASE_URL 并启动（建表自动完成）
export DATABASE_URL="postgresql+psycopg://user:password@localhost:5432/logistics_copilot"
python scripts/mock_data.py --force   # 重新灌入模拟数据
python scripts/sync_kb.py             # 同步知识库
python -m uvicorn app.main:app --port 8000

# ④ 验证
curl http://127.0.0.1:8000/api/health   # db_dialect 应显示 postgresql
```

MySQL 同理，`/api/health` 的 `db_dialect` 显示 `mysql` 即切换成功。

## 3. Alembic 迁移（预留，生产建议用迁移代替 create_all）

```bash
pip install alembic
export DATABASE_URL="postgresql+psycopg://..."    # alembic/env.py 自动读取
alembic revision --autogenerate -m "init tables"  # 基于 app/models.py 生成迁移
alembic upgrade head
```

## 4. 可移植性设计说明

| 设计点 | 做法 |
|---|---|
| 时间字段 | 统一 `TEXT` 存 `YYYY-MM-DD HH:MM:SS`，字符串比较即时间比较，三库行为一致 |
| 日期分组/今日筛选 | `substr(created_at,1,10)` + 字符串比较 —— 标准 SQL，三库通用 |
| 响应时长计算 | 时间差函数是方言差异：SQLite `julianday` / MySQL `TIMESTAMPDIFF` / PostgreSQL `EXTRACT(EPOCH FROM ...)`，在 `app/dashboard.py` 按方言分支，其余方言自动回退 Python 计算 |
| 主键自增 | ORM 层 `Integer primary key autoincrement=True`，由各库方言自行渲染 |
| 引擎参数 | 仅 SQLite 需要 `check_same_thread=False`，已在引擎层按 URL 前缀条件化，不影响其他库 |

## 5. 边界与建议

- 演示/单机场景：SQLite 零运维、万级数据足够；
- 多人并发/上量：切 PostgreSQL（本仓库所有聚合 SQL 已验证可移植）；
- 注意：切换数据库后历史数据不迁移（本项目为模拟数据，直接重跑 `mock_data.py` 即可）；真实生产迁移需另做 ETL。
